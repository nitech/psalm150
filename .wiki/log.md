# Directory Update Log

## 2026-09-24
* **Creation**: [Server library](concepts/server-library.md) page. Connecting no longer needs a pasted token: Settings checks the server URL as it is typed (`probe_song_server`, `GET /api/v1/info`) and **Sign in with browser** (`sign_in_server_library`, `cancel_server_sign_in`) opens the default browser on the server, receives a one-time code on a `127.0.0.1` loopback redirect and exchanges it with a PKCE verifier for a desktop token. The token field moved into a "Use a desktop token instead" section.
* **Sync**: Saving in a server library works: `save_song` / `save_song_lines` are async and send the edit to the song server with the manifest revision as base (409 → nothing changes, the message says to synchronize), then update the offline copy and the manifest revision. Before, the save failed on the forced read-only flag and the error toast was hidden behind the editor.
* **Sync**: Toasts are drawn above open dialogs; the raw editor closes after a successful save.
* **Sync**: Search matches every word in title, lyrics or tags with spelling tolerance (`src-tauri/src/search.rs`, cached per index); hits carry `match_rank` and the list sorts by rank before the chosen column. A search with exactly one hit selects and shows it.
* **Sync**: Fixed shortcuts Ctrl+E (search, text selected) and Ctrl+1–4 (Search, Setlist, History, Favourites); the search field selects its text whenever it gains focus.

* **Sync**: VSB sync writes edits and deletions back to a song server through the device token (`PUT`/`DELETE /songs/{id}` with base revisions from the export's `psa150-manifest.json`, saved as `manifest.json` beside the replica); server-library syncs wait while projecting.

* **Sync**: MDB import places chords at their column on the untrimmed VSB row (indented chord rows were shifted left). VSB and ChordPro chord regexes are compiled once.

## 2026-09-13
* **Creation**: The Settings dialog now uses a persistent category menu and a top-level “Find a setting” search. The search filters to matching setting groups and preserves all existing library, server, projection, search, remote, report, and shortcut controls.
* **Sync**: Song loading is now preview-only and `project_song` creates an explicit active session. Console, audience and stage consume one revisioned `projection-updated` snapshot; saving the active song updates immediately while previewing or saving another song leaves it untouched. The stage keeps its text while the audience is blank.
* **Sync**: Song writes validate local `.pro`/`.cho` filenames, use content hashes to reject outside edits, retain verified recovery copies and install verified reserved temp files. Web saves use collision-free number/title names. Line corrections are applied in Rust through parser source-line mappings.
* **Creation**: Settings gained manual duplicate review with exact number/title/lyrics grouping, side-by-side lyrics/chords/raw ChordPro, content-hash pair decisions, guarded recoverable deletion and restore. Review and recovery data are per-library local app data.
* **Sync**: MDB import skips existing files, reports imported/skipped/failed files, allows one bound import at a time, stops further writes on read-only/library changes, preserves existing themes and reindexes completed partial work. Integration tests now use repository fixtures and temporary folders rather than `C:\temp`.
* **Sync**: Operator console gained numbered stanza buttons and digit-key navigation, including multi-digit numbers with a 600 ms prefix timeout. Numbers follow the audience stanza counter, jump to the first slide of split stanzas, and unblank. Pending input survives ordinary navigation/preview and resets for focus changes, other keys, pointer presses, session/structure changes and projection close. Timing and stanza mapping are covered by `tests/stanza-number-input.test.ts`.

## 2026-08-30
* **Sync**: Remote control is now usable from a phone: Settings gained a "Phone remote" toggle, `setup()` auto-starts the server when `config.remote_enabled` is true, `RemoteServer` binds synchronously (bind errors reach the caller), stops within 250 ms and releases the port, `GET /` is served as HTML, and the page remembers the PIN and reports each tap. Integration test in `src-tauri/tests/remote.rs`.

## 2026-08-29
* **Creation**: Bundle initialised from a full read of the repo: overview, 19 concept pages, index, this log. Sources are cited per page; `/docs/` and `/CONCEPTS.md` stay where they are and are linked, not copied.
* **Sync**: Audience display — lyric lines no longer wrap mid-line. `.audience-content` is laid out at natural width (`white-space: pre`) and `fit()` scales the block to the screen; only a line wider than 1/0.7 of the available width falls back to balanced wrapping (`src/audience-fit.ts`, tested). The old `max-width` subtracted the theme margins a second time, which is why the 960 px simulated display wrapped so early.
* **Sync**: Operator console — the song list gained Song / No / Key column headers that sort (default Song ascending; persisted as `localStorage["psa150-song-sort"]`; History and Setlist tabs keep their own order) and a Settings toggle for the number column (`config.show_song_numbers`, default on; new command `set_show_song_numbers`). The list is one CSS grid with subgrid rows, so No and Key are as narrow as their widest value and the title gets the rest; the sticky header lives inside `psa150-song-list` and emits `psa150-sort`.
