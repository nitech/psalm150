# Directory Update Log

## 2026-09-27
* **Sets**: Church sets (ordered song lists for a service). New `GET /sets?from=&limit=`, `GET /sets/snapshot`, `POST /sets` (optional client id, 409 when taken), `GET /sets/{id}`, `PUT /sets/{id}` (`base_version`, 409 when stale, items replaced) and `DELETE /sets/{id}?base_version=` (soft). Reads for any token; writes through `require_song_editor` (owners, leaders, desktops). Migration `0004_song_sets.sql` (`song_sets`, `song_set_items`). The desktop syncs sets through the snapshot, fetches missing songs one by one and keeps a losing edit as a copy. New page [sets](concepts/sets.md).
* **Remote control**: In-memory relay (`AppState.remote`). Desktops `PUT`/`DELETE /remote/desktop` and long-poll `GET /remote/desktop/commands?wait=`; any token lists `GET /remote/desktops`; person leaders send `POST /remote/desktops/{device_id}/commands` (202; 404 not online, 409 not accepting). 45 s online window, 30 s command expiry, 20 queued, 24 h forget, lost on restart. New page [remote control](concepts/remote-control.md).
* **Web client**: Rewritten mobile-first with hash routes, bottom tabs or side rail, song reader with chords and transpose, set editor, service view with swipe, wake lock and "Follow the desktop", remote screen and More screen; viewers see no edit or steering controls; theme and reader preferences in `localStorage`; shared `psa150-tokens.css` copied from the desktop. Vitest tests (`bun run test`) now run in CI.
* Pages touched: api-contract, data-model, auth-and-roles, desktop-sync, web-client, build-and-ci, gaps, overview (desktop token rule and `AppState`), songs-and-revisions (song delete exists); new sets and remote-control. `/docs/api.md`, `/TODO.md`, `/README.md`, `/AGENTS.md` and CI updated to match.

## 2026-09-24
* **Auth**: Desktop browser sign-in. New public `GET /info` ping, `POST /desktop-auth/codes` (editor session; `{device_name, code_challenge}` to `{code, expires_at}`, a `psa_c_` code valid 5 minutes) and public `POST /desktop-auth/token` (`{code, code_verifier}` to `{token, device_id, device_name, church_name}`; single use, S256 PKCE, the approver must still be an active owner or leader). Migration `0003_desktop_auth_codes.sql`. The web client shows a "Connect this desktop?" consent screen for `/?desktop_redirect=…` and redirects only to `http:` loopback URLs with a port. Pages touched: api-contract, auth-and-roles, web-client, data-model, desktop-sync.
