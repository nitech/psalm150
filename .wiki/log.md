# Directory Update Log

## 2026-10-23
* **New songs get a number; search index fix**: a song saved from an online search without a number gets the highest number in the library plus one (`Database::next_song_num`), in the file as `{meta: song_num=N}` and in its name; a server library keeps it (the server only numbers songs that come without one). `upsert_song` and `delete_song` now take a song out of `song_search` with the FTS5 `'delete'` command before `songs` changes; the plain `DELETE` used before failed with "database disk image is malformed" for a song never indexed. Tested. Pages touched: library-index, web-search.
* **Save found songs to a server library**: `save_web_song` is async and, in a server library, creates the song on the song server (`POST /songs` with the device token) and writes it into the offline copy and manifest, instead of refusing as read-only. Pages touched: web-search, gaps.
* **Online search only when asked**: a search with no library match no longer looks online after a pause. The list offers "No songs match "…"" with **Search online** (or Enter); while it runs it shows a spinner and **Cancel**, then "Found online" rows, "Nothing found online" or the error with Try again (`src/online-search.ts`, tested). `search_web_songs` is async now, so the search no longer blocks the main thread. The old scrapers in `src-tauri/src/web_search/` are replaced by the `psa150-lyrics` crate, shared with the song server and mirrored into `src-tauri/crates/psa150-lyrics/` by `bun run sync:shared` (now also a folder mirror; the workflow is "Shared files"). Results are cleaner: real titles and artists, more header styles, chords at their columns, repeats written out, clutter dropped, duplicates merged. Results take 1–2 s. Candidates gain `artist`. Settings label: "Offer to search online when no songs match". Recorded the rule that the app works without a song server. Pages touched: web-search, standalone (new), overview, config, ipc-contract, gaps, chordpro-dialect, index.

Closing the main window now exits the app. The `process` plugin, its JS packages and the `desktop` capability are gone. With a server library connected, an update is taken only when the server's `desktop_api` (`GET /api/v1/info`, missing = 1) is at least the release's `desktop_api` in `latest.json` (stamped from `REQUIRED_DESKTOP_API`, now 1); otherwise it waits and a held download is withdrawn (`update-ready` null). Pages touched: [build and release](concepts/build-and-release.md), [IPC contract](concepts/ipc-contract.md), [operator console](concepts/operator-console.md), index.

* **Creation**: [Design tokens](concepts/design-tokens.md) page. `src/psa150-tokens.css` holds the shared `--psa-*` tokens (dark and light themes), mirrored byte-for-byte in the song server's `web/src/psa150-tokens.css`; `styles.css` imports it and keeps its own names as aliases; `index.html`, `audience.html` and `stage.html` set `data-theme="dark"`. `designsystem.json` is now the "PSA150 Design System" reference and names the stylesheet as the source of truth.
* **Sync**: Sets sync ([server library](concepts/server-library.md#sets), [setlists](concepts/setlists.md)): in a server library setlists mirror the church's sets (same ids, `Setlist.server { version, dirty }`, `SetlistItem.note`). Edits are marked dirty and uploaded (`POST` with the id, or `PUT` with `base_version`); 409/404 keeps the server's version and saves the local edit as "<name> (changes from <computer>)"; songs not on the server are left out (`skipped_items`). Runs every 60 s, after edits, after a full Synchronize and on the new `sync_server_sets`; emits `setlists-changed`.
* **Sync**: Song server remote ([remote control](concepts/remote-control.md#through-the-song-server)): opt-in `server_remote_enabled` (Settings, Church server, "Allow remote control through the song server"; `set_server_remote_enabled`). The desktop reports its state (`PUT /api/v1/remote/desktop`, heartbeat 15 s, `DELETE` when off) and long-polls commands; next/previous/blank/show_slide run in Rust, project_song and project_set_item reach the console as `remote-project`. New `set_active_setlist` tells the backend the console's setlist.
* **Sync**: Operator console: Next song applies the set item's transpose; `setlists-changed` refreshes setlists with toasts for conflicts and skipped items ([operator console](concepts/operator-console.md), [IPC contract](concepts/ipc-contract.md), [config](concepts/config.md), [gaps](concepts/gaps.md)).
