# Directory Update Log

## 2026-10-03
* **Song permalinks**: `GET /songs/{id}` (outside `/api`, only with a web build) serves the app's `index.html`. For a song in a public library it also carries the song's title and Open Graph tags for link previews; private songs get the plain page. The web client's **Share** copies this permalink and turns it into `#/songs/{id}` on load. The song reader sets the tab title. `sw.js` no longer saves permalink pages over the cached `/`.
* **Copying lyrics**: a **Copy the words** button on the song reader, and lyrics-only Ctrl+C (`installLyricsCopy`): no section labels, chords or comments. New `copy` icon in `shared/icons.ts`. Vitest `song-text.test.ts`.
* **Web client**: the song-number column is hidden for songs without a number.
* Pages touched: web-client, deployment, index.
* **Song numbers**: metadata extraction now reads the desktop's `{meta: song_num=N}` (after `{number}`/`{song_number}`), and migration `0006_desktop_song_numbers.sql` fills `song_number` for revisions stored before. `GET /songs` and `/public/songs` take `sort=title|number` and `direction=asc|desc` (number: numeric, songs without one last in both directions; 400 for other values). The web list shows the number column left of the title and a **No** / **Song** sort header like the desktop's, remembered in `localStorage`. The song list always has its sticky bar, so songs no longer show between it and the sticky search field.
* Pages touched: songs-and-revisions, api-contract, data-model, web-client, index. `/docs/api.md` updated.
* **Web client, phones**: the bottom tab bar is replaced by a ☰ drawer (the sections rail, off-canvas) that closes by swiping it left, tapping the shade, Escape or picking a section. The song list starts with ☰, search and New, runs edge to edge, and shows only number and title on one 44 px line; bars stay solid in the page colour; the church name over the tab screens shows only on wide screens. New `menu` icon in `shared/icons.ts`. Pages touched: web-client.

## 2026-10-02
* **Public library**: An owner can make the church's whole library readable without signing in. Migration `0005_public_library.sql` adds `churches.public_library`. New `GET /church` (any token), `PUT /church` (person owner only, `require_owner`), and token-free `GET /public/songs` and `GET /public/songs/{id}`. `GET /info` gains `public_library` and `public_library_name`. Sets, revisions, export and writes stay behind a token.
* **Web client**: Boot reads `/info`. With a public library, signed-out visitors get **Songs** and **Sign in** tabs, and members' routes open sign-in. The song reader has **Share**, which copies the song's address. Owners switch **Who can read the songs** under More. `sw.js` caches `/info` and the public song reads. New `login` and `share` icons in `shared/icons.ts`. **Show more songs** stays hidden once the list is complete.
* Pages touched: api-contract, auth-and-roles, data-model, web-client, gaps, index. `/docs/api.md` updated.

## 2026-09-28
* **Web client UX**: A per-phone **current set** (the next service unless one is chosen on the phone) with a bar above the tab bar, one-tap ＋/✓ on song rows and an **Add to <set>** button on the song page, each with Undo; edits read fresh and retry a 409 once. Sticky header bar (title appears once the large title scrolls away; auto-hides while reading), sticky song search, reader settings in a panel under the bar, Back restores the scroll position. Song list pages 100 at a time. Undated sets get a "No date" group. Set editor: drag by grip, picker marks songs already in the set. Polling stops while the page is hidden. Installable: favicon, touch and maskable icons, `manifest.webmanifest`, and `sw.js` caching the app, bundles and song/set reads for offline use (the current set's songs are fetched ahead). The session moved from `sessionStorage` to `localStorage`; sign-out clears cached data.
* **API**: `GET /songs` takes `offset` for paging; order gains `s.id` as a final tiebreak.
* Pages touched: web-client, api-contract, songs-and-revisions, auth-and-roles, gaps, index. `/docs/api.md` updated.
* **Shared UI assets**: `shared/psa150-tokens.css` and `shared/icons.ts` are now canonical here for both apps (the desktop used to own the tokens). The web client imports them directly; the Docker build copies `shared/`. The desktop mirrors them in `src/shared/` and its CI fails when the mirror drifts. Icons merged: the web client now uses the desktop's `edit` and `blank` geometry.
* Pages touched: web-client. `/AGENTS.md` updated to match.

## 2026-09-27
* **Sets**: Church sets (ordered song lists for a service). New `GET /sets?from=&limit=`, `GET /sets/snapshot`, `POST /sets` (optional client id, 409 when taken), `GET /sets/{id}`, `PUT /sets/{id}` (`base_version`, 409 when stale, items replaced) and `DELETE /sets/{id}?base_version=` (soft). Reads for any token; writes through `require_song_editor` (owners, leaders, desktops). Migration `0004_song_sets.sql` (`song_sets`, `song_set_items`). The desktop syncs sets through the snapshot, fetches missing songs one by one and keeps a losing edit as a copy. New page [sets](concepts/sets.md).
* **Remote control**: In-memory relay (`AppState.remote`). Desktops `PUT`/`DELETE /remote/desktop` and long-poll `GET /remote/desktop/commands?wait=`; any token lists `GET /remote/desktops`; person leaders send `POST /remote/desktops/{device_id}/commands` (202; 404 not online, 409 not accepting). 45 s online window, 30 s command expiry, 20 queued, 24 h forget, lost on restart. New page [remote control](concepts/remote-control.md).
* **Web client**: Rewritten mobile-first with hash routes, bottom tabs or side rail, song reader with chords and transpose, set editor, service view with swipe, wake lock and "Follow the desktop", remote screen and More screen; viewers see no edit or steering controls; theme and reader preferences in `localStorage`; shared `psa150-tokens.css` copied from the desktop. Vitest tests (`bun run test`) now run in CI.
* Pages touched: api-contract, data-model, auth-and-roles, desktop-sync, web-client, build-and-ci, gaps, overview (desktop token rule and `AppState`), songs-and-revisions (song delete exists); new sets and remote-control. `/docs/api.md`, `/TODO.md`, `/README.md`, `/AGENTS.md` and CI updated to match.

## 2026-09-24
* **Auth**: Desktop browser sign-in. New public `GET /info` ping, `POST /desktop-auth/codes` (editor session; `{device_name, code_challenge}` to `{code, expires_at}`, a `psa_c_` code valid 5 minutes) and public `POST /desktop-auth/token` (`{code, code_verifier}` to `{token, device_id, device_name, church_name}`; single use, S256 PKCE, the approver must still be an active owner or leader). Migration `0003_desktop_auth_codes.sql`. The web client shows a "Connect this desktop?" consent screen for `/?desktop_redirect=…` and redirects only to `http:` loopback URLs with a port. Pages touched: api-contract, auth-and-roles, web-client, data-model, desktop-sync.
