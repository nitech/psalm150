# Psalm150 Song Server

Optional, self-hosted, API-first song library for Psalm150: a Rust/Axum API on PostgreSQL with a mobile-first Vite web client. Start at [overview](overview.md).

# Contracts

* [API contract](concepts/api-contract.md) - Every `/api/v1` endpoint with auth, limits and status codes (including `/info`, `/church`, `/session`, `/account/password`, `/api-tokens*`, `/members*`, `/public/songs*`, `/songs/deleted` and restore, revision reads, `/desktop-auth/*`, `/sets*` and their share links, `/public/sets*`, `/remote/*` with its event stream, room renames and `/public/rooms*`); error body; hand-maintained OpenAPI with summaries, sections, the `bearer` scheme and its route check; who calls what
* [Data model](concepts/data-model.md) - PostgreSQL tables (including `desktop_auth_codes`, `song_sets`, `song_set_items`, `api_tokens`), church scoping, cascades, indexes, `churches.public_library` and `public_rooms`, desktop room names unique on the server, migrations 0001–0016 at startup (0010: trigram indexes for search; 0011: set share links; 0012: song keys; 0013: invite and reset links; 0014: song recordings and videos; 0015: recordings moved to files; 0016: video links dropped for song metadata) (usernames freed on removal), stored-but-unused columns
* [Auth and roles](concepts/auth-and-roles.md) - First-run setup, `psa_s_` sessions, `psa_a_` API tokens (a person's access, capped by role), `psa_d_` desktop tokens, desktop browser sign-in (`psa_c_` code with PKCE), sign-out and password change, limits on wrong passwords (429, per username, client and person), owners managing members (last-owner and other-church rules, reusable usernames), one-time invite and password reset links, public library and public rooms, who may rename a room, hashing, the role matrix, what is still missing

# Songs

* [Songs and revisions](concepts/songs-and-revisions.md) - Raw ChordPro, extracted metadata, exact-bytes content hash, base-revision 409 conflicts, reading any revision, deleting and restoring, recordings of how a song is played (`/songs/{id}/recordings`, audio as files under `PSA150_MEDIA_DIR`, streamed with `Range`, play links), the YouTube video as `{meta: youtube}`, how search matches (lyrics from three letters, wildcards escaped, trigram-indexed) and sorts (title, number or key), key filter and key counts
* [Import and export](concepts/import-export.md) - 500-song batch import with hash dedup and per-church lock; ZIP export of `.pro` files, their names and the id manifest
* [Sets](concepts/sets.md) - Ordered song lists for a service shared by the church; item rules and limits, paging, client-chosen ids, `base_version` 409s, soft delete and restore, deleted songs as `song: null`
* [Shared sets](concepts/shared-sets.md) - A leader shares one set on a link (`/shared/{key}`): anyone with it reads the set and its songs without an account; read-only or editable (add and remove songs only); `/sets/{id}/share` for leaders, token-free `/public/sets/{key}*`; key stored unhashed so it can be copied again; stop, delete and restore; the Share sheet and the shared page; leading a set live (`/sets/{id}/live`, `/public/sets/{key}/live/events`, in memory) with a watching count; no rate limit yet
* [Online song search](concepts/online-search.md) - A song the library lacks: the shared `psa150-lyrics` crate in `shared/lyrics/` (mirrored by the desktop, which must work without a server), search engine and chart sites, page text to ChordPro, ranking and duplicates; `GET /songs/online` for song editors with 6 h memory and 2 at once; the web client's offer, Cancel and check-in-the-editor flow
* [Desktop sync](concepts/desktop-sync.md) - Connecting via `/info` and browser sign-in; Phase 1 merge-then-pull; set sync through `/sets/snapshot` with conflict copies on the desktop; offline guarantees, duplicate pitfalls
* [Remote control](concepts/remote-control.md) - In-memory relay: desktops report state (with slide words) and long-poll for commands, leaders' phones follow the desktop list live (server-sent events over `fetch`) and send next/previous/blank/slide/project; 45 s online, 30 s command expiry, 20 queued, revoked desktops dropped at once, single instance
* [Rooms](concepts/rooms.md) - Every desktop's flower room name, unique on the server; renaming by the desktop or a leader; the owner's `public_rooms` and the desktop's `shares_room`; token-free `/public/rooms/{name}` and its event stream; the `/join` page with large text, high contrast, follow and wake lock; no rate limit or viewer cap yet

# Operating

* [Web client](concepts/web-client.md) - Mobile-first hash-routed app: public-library visitor shell, song Share permalink, lyrics-only copy, sticky bars, the current set with one-tap adding and Undo, paged song list with a number column, No/Song/Key sort and a key filter sheet, song reader with chords and transpose, recording and YouTube pills under a song's title (record from ⋮ or +, play, delete), how to play a tapped chord (guitar and piano, swipe, Play), set editor with drag to reorder, service view with swipe and Follow, remote screen with live push, room names, the current slide's words, rename and room link, the `/join` room reader, following the projector from the dock, invite and reset link pages, More (install, theme, import/export, rooms switch, desktops); API tokens, your password and the API reference (`#/api`, `/api/docs`) under More → About; People for owners; role refresh from `GET /session`; sign-out that revokes the session; installable app with offline copies; role handling; storage; shared design tokens; desktop consent screen
* [Accessibility](concepts/accessibility.md) - WCAG 2.2 AA for the web client and `/join`: screen titles, skip link, landmarks, focus on route change and back from sheets and the drawer, radio groups, live announcements, toast timing, contrast and "on" indicators beyond colour, scroll padding, reflow at 320 px; how to test (axe in both themes at phone and desktop size, keyboard scripts, screen readers); exceptions (song language, live rooms, 7-day sessions)
* [Deployment and config](concepts/deployment.md) - Env vars with defaults (including `PSA150_CLIENT_IP_HEADER`), a reverse proxy that must not buffer `text/event-stream`, the `/join` pages, Docker Compose, the three-stage image, the `/songs/{id}` permalink page with link-preview tags, security headers (CSP, nosniff, no framing, no referrer), headless mode, shutdown
* [Build and CI](concepts/build-and-ci.md) - Commands per half, the version bump on every commit, the API integration tests (including API tokens, members, passwords, restore, rooms and their event streams, and the OpenAPI check) and web vitest tests and their coverage, the three CI jobs
* [Gaps and backlog](concepts/gaps.md) - TODO status, design-vs-code differences, behaviour gaps, unused schema and endpoints
